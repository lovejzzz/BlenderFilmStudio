# PC9：真实尺度物理原型预注册

## 为什么不是继续修木块

PC8 已证明软件能让 Blender/Bullet 决定运动，并从实际屏幕速度自动决定快门；但画面仍像精致的抽象演示。旧 PC5 的三瓶轮廓更容易识别，却用了约 84 cm 直径的球、1.44 m 高的瓶子和三个手填相同质量。它证明了因果和程序建模，没有证明真实尺度物性。

PC9 不为某一帧摆姿势，也不靠更多装饰掩盖物理。它把“篮球”和“装液体的瓶子”变成软件可理解的物理原型：统一使用米、千克、升；可见填充量同时决定液体几何、总质量和刚体原点重心。

## 冻结课程

- 一个半径 `0.12 m`、质量 `0.624 kg` 的程序化篮球。
- 三个高 `0.28 m`、主体半径 `0.034 m` 的程序化有盖瓶。
- 填充比例：`0.15 / 0.55 / 0.90`。
- 由同一填充输入推导的质量：`0.10685 / 0.30645 / 0.48110 kg`。
- 推导重心高度：`0.05469894 / 0.06743313 / 0.09645380 m`。
- 瓶身可见阶段：base、body、shoulder、neck、cap、label、liquid fill。
- 碰撞采用可见瓶身 mesh 的 `CONVEX_HULL`，不能用与外形不一致的装饰代理。
- Bullet 独占 release 后与最终姿态；所有 target pose key 和 release 后 ball pose key 必须为 0。

填充是静态物理近似，不声称模拟液体晃动。PC9 的目标是先让质量、重心与可见状态一致，而不是伪造流体效果。

## 产品规则

新增 `bfs.causalSceneSpec.v0.5` 与 `FILLED_LATHED_BOTTLE` allowlisted factory；保留 v0.1/v0.2/v0.4 逐项兼容。只允许修改 `scripts/modules/film_studio_causal.py`，不能按 PC9 名称、fixture hash 或特定坐标分支，也不能引入 Python、shell、网络或任意路径权限。

## 验收

机器必须证明真实尺度、精确质量/重心推导、三种可见填充、匹配可见瓶身的碰撞 hull、三瓶都由 Bullet 响应、至少两瓶最终超过 60°、全部超过 25°、24 帧连续片段、实测原生 motion blur、零最终姿态权力和 reopen exact。

我还必须直接回答七个画面问题：是不是一眼能认出篮球和三瓶；比例是否可信；三种液位是否可见；碰撞是否连续传播；模糊是否保留轮廓/瓶盖/标签/接触方向；结局是否像求解出来而不是摆好；材质与接触影是否确实比 PC8 木块更可信。任一答案为 NO，PC9 保留失败，不能调低门槛或手摆一张更好看的图。

## 边界

PC9 PASS 只证明一个真实尺度篮球/装液瓶课程进入产品。它不证明液体晃动、软体变形、照片级真实、广泛资产泛化或机器人 capstone。机器人继续保持不变，等这些通用规则成熟后再做陌生项目考试。
