# B53-E1 · Formal runner admission path totality protocol

Date: 2026-08-28  
Type: zero-Blender execution-infrastructure experiment  
Status at protocol creation: preregistration only

## Research question

Can one reusable admission module make equivalent relative, dot-segment and absolute repository paths produce the same canonical evidence identity, reject path/evidence freshness violations with exact reasons, and still emit a self-hashed failure receipt before any formal work begins?

## Why this is the next gap

Three preserved failures form an evidence chain rather than an abstract code-quality preference:

1. B42 could not launch any worker because the nested writable mountpoint did not exist; its analyzer also dereferenced a null observation.
2. B52-D12.14-H1 rendered all formal sources, but producer-only preflight did not exercise the analyzer's actual schema-consumer boundary.
3. B52-D12.14-H2 strengthened that boundary and passed a 15/15 full-shaped preflight, yet the formal runner's own CLI admission failed before its `try/finally`: a relative `preflight-root` was passed to `Path.relative_to()` against an absolute repository root.

H2 is closed with `scientificVerdict=null`; absolute-path retry or runner repair under the same ID is forbidden. B53-E1 studies the general infrastructure defect with new files, tools and evidence.

## Frozen intervention

The implementation may create exactly three new tools after this protocol is committed and pushed:

- a dependency-free Node admission library;
- a single-use runner that creates an isolated local Git fixture and evaluates the 17 frozen cases;
- an independent auditor that replays records and performs at least 32 semantic attacks.

The fixture uses a local bare Git origin. It performs no fetch, HTTP, SSH, package install, Blender, Docker, model or render operation. A separately declared attempt-ledger root must be created before semantic evidence/output admission so every expected rejection can still produce `failure.json` and `receipt.json`.

## Positive equivalence gate

`P01_RELATIVE`, `P02_DOT_SEGMENTS` and `P03_ABSOLUTE` must all accept. Their caller spellings differ, but their evidence canonical identity must be exact. Their output target basenames may differ; the canonical parent identity and freshness decision must be exact. Admission returns paths but must not create any declared formal output.

## Negative reason gate

Fourteen cases each freeze one earliest expected reason: outside repository, symlink alias, missing/not-directory evidence, untracked evidence, committed-not-pushed evidence, preflight self-hash/status, tool hash, outside/symlink/existing output and missing origin branch. A later error cannot mask an earlier frozen reason. Every rejected case must write one failure and one receipt with `scientificVerdict=null`.

## Audit

The independent auditor must not import the admission library or runner. It reopens the fixture Git repository, recomputes canonical hashes and path identities, verifies the local bare-origin ancestry observations, checks that no declared formal output or outside/symlink target was written, replays process counts, and executes at least 32 one-field semantic attacks against copied records. Verdict-label validation is outcome-neutral: it checks the mapping implied by observed gates rather than requiring support.

## Success boundary

Support requires all 14 named gates, all 17 frozen case outcomes/reasons, receipt totality and the attack minimum. Tool/process failure invalidates the experiment with no scientific verdict and forbids same-ID repair. A supported result authorizes only later preregistered adoption by future runners; it does not modify H2 or production compiler orchestration and does not replace B01/B02 structure-hash regression tests.
