# PixelSpec v0.1 — 4K OpenEXR reproducibility and mastering experiment

Snapshot: 2026-08-26

Status: executed on Blender 5.2.0 LTS, macOS arm64, Cycles CPU

## Question

Under a pinned same-machine environment, can compiled B01/B02 scenes produce repeatable 4K final pixels, complete multi-layer data, finite values, and a delivery-metadata-complete OpenEXR master without changing image content?

This experiment separates three acceptance units:

1. Rendered pixel content, compared after OpenEXR decoding per subimage.
2. OpenEXR container bytes, recorded as SHA-256 but not treated as pixel identity.
3. Delivery metadata, checked independently and corrected by a verified mastering transform when Blender's native writer omits required attributes.

## Locked environment

- Blender `5.2.0 LTS`, build `fbe6228777e7`.
- Cycles CPU, fixed 8 threads.
- 3840×2160, 512 samples, fixed shot seed, animated seed disabled.
- OpenEXR multipart, HALF, ZIP lossless.
- OCIO config `cg-config-v4.0.0_aces-v2.0_ocio-v2.5`.
- OCIO file SHA-256 `24ec81841048fc5db160a7bad882263246183385c5d49d0e86e11464917ead15`.
- Scene-linear role `ACEScg`.
- OpenImageIO `3.1.13.1`, bundled with Blender.

## OpenEXR structure

Blender wrote eight multipart subimages:

1. `BFS_MASTER.Combined` — RGBA.
2. `BFS_MASTER.Depth` — Z.
3. `BFS_MASTER.Normal` — XYZ.
4. `BFS_MASTER.Vector` — XYZW.
5. `BFS_MASTER.CryptoObject00` — RGBA.
6. `BFS_MASTER.CryptoObject01` — RGBA.
7. `BFS_MASTER.CryptoObject02` — RGBA.
8. `BFS_MASTER.Noisy Image` — RGBA.

All parts were exactly 3840×2160. Every required logical pass was found. No NaN or Infinity value was found in any channel.

## Negative result — native Blender metadata

Blender's native multipart EXR output did not contain the OutputSpec-required attributes:

- `chromaticities`;
- `framesPerSecond`;
- `timeCode`;
- `owner`;
- `comments`.

The render therefore passed pixel and channel conformance but failed native delivery-metadata conformance. This failure is retained in `experiments/pixel-v0-1/results.json`.

## Mastering result

`blender/master_exr.py` uses Blender's bundled OpenImageIO to copy each multipart subimage and add:

- ACEScg AP1/D60 chromaticities;
- 24/1 frame rate;
- packed SMPTE time code;
- owner and comments (read back through OIIO canonical aliases `Copyright` and `ImageDescription`);
- a mastering-tool provenance marker.

All four selected frames passed mastering:

- all five required attributes present;
- all required passes preserved;
- all values finite;
- all output pixels exactly equal to the source pixels.

## Measured cost baseline

- Eight formal renders: `2,621.16` seconds total.
- Mean: `327.65` seconds per 4K frame.
- At 24 fps, serial machine time is about `2.18` hours per second of finished footage.
- Mean source EXR size across the four unique frames: about `140 MB`.
- Approximate uncompressed production rate at this sample: `3.36 GB` per second of footage before proxies, backups, or multiple versions.

These scenes are simple. The numbers are a measured lower-complexity baseline, not a film-project quotation.

## Explicit non-claims

- Same-machine CPU exactness does not establish cross-GPU, cross-driver, cross-OS, or cross-version tolerance.
- Four representative frames do not establish stability for every frame of B02.
- No actor, rig, facial performance, cloth, hair, fluid, or volume simulation was tested.
- Numerical conformance does not establish cinematic quality.
- ACEScg encoding and a pinned OCIO config do not calibrate a physical review display.
- Metadata conformance does not create a DCP or prove DCI compliance.
